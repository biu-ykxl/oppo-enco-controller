# 真机验证记录 —— OPPO Enco Free4 丹拿版（`06C010`）

环境：Windows 11 / 耳机 `AA:BB:CC:DD:EE:FF`（已隐去真实地址） / 蓝牙音频已连接 / 无欢律占用。
下面所有报文均为真实抓取，ack 状态字节 `00` = 成功。

## 1. 连接

| 项 | 结果 |
|---|---|
| RFCOMM 通道 | **15**（0.14s 直连）；12 与 1..30 作兜底扫描 |
| 通道有效性 | 连上后发电量查询，收到 `0x8106` 才认定是控制通道 |
| 产品 ID `0x0103` | `00 10 C0 06` → **06C010**（丹拿版） |
| 固件 `0x0105` | `1,2,118 / 2,2,118 / 3,1,105` → 左 118、右 118、盒 105 |

> 通道 3（HFP）也曾接受连接，但所有命令静默超时 —— 这就是必须做应答校验的原因。

## 2. 降噪（`0x010C` / `0x0404`）

查询请求 `01 01`，回复 `status + 2 字节回显 + 状态位图`；位索引是**叶子档位 ID**。

| 发送 index | 回复位图 | 实际生效 |
|---|---|---|
| 0 / 3 | `08 00` | 3 关闭 |
| 1 / 6 | `40 00` | 6 轻度降噪 |
| 2 / 8 | `00 01` | 8 通透 |
| 4 | `10 00` | 4 深度降噪 |
| 5 | `20 00` | 5 中度降噪 |
| 7 | `80 00` | 7 智能降噪 |
| 11 | `00 08` | 11 智能自适应 |
| 9 / 10 | `00 02` | 9（语义未标注） |
| 12 | `00 08` | 回退到 11 |

`0x0404` 的 ack 恒为 `00`，不能作为成功依据，必须回读 `0x010C`。

## 3. 音效（`0x0122` / `0x0406` / `0x010F`）

`0x0122` payload `01 05`，回复 110 字节、count=3，条目布局
`[selected][min][max][eqId][nameLen][name UTF-8][bandCount][(freq LE16, gain int8)*]`：

| eqId | 名称 | 六段增益 |
|---|---|---|
| 4 | 均衡耐听 | 62Hz+2 · 250Hz−1 · 1k+4 · 4k+2 · 8k+0 · 16k+3 |
| 5 | 人声凸显 | 62Hz−4 · 250Hz+3 · 1k+2 · 4k−2 · 8k+3 · 16k+0 |
| 6 | 声场增强 | 62Hz+1 · 250Hz+4 · 1k+6 · 4k+3 · 8k+0 · 16k+1 |

- min/max 实测 `0xFA`(−6) / `0x06`(+6)，增益为有符号字节。
- 切换 `0x0406 [id]` → ack `00`，`0x010F` 回读 4/5/6 全部一致。
- **`0x0122` 只返回具名/自定义预设**，内置 0~3 不在此列表，界面做合并去重。

## 4. Hi-Res / 码率（`0x0403` feature `0x18`）

| 载荷 | ack | 结果 |
|---|---|---|
| `18 00` | `00` | 标准码率 |
| `18 02` | `00` | Hi-Res 高清 |
| `18 01` | 无 ack | **耳机断开 RFCOMM（10053）** |
| `18 03` | 无 ack | **再次断链** |

结论：`0x18` 是枚举 0/2，不是布尔；其余值会让耳机踢掉链路。
白名单 `spatialHiResMutex`（空间音频与 Hi-Res 互斥）印证其语义。

### 码率为什么读不到

- 扫遍设备声明的 25 个 `0x01xx` 查询：无一返回编码/码率。
  `0x0107` = `00 02 01 03 02 00`、`0x0109` = `00 03 01 04 02 07 03 04`、`0x0114` = `00 02`，
  官方 SDK 里前两条同样是「未解析轮询」。
- `Get-PnpDeviceProperty` 查 A2DP 节点：无 codec / bitrate 属性。
- 可用的是 Core Audio `GetMixFormat`（`oppo/audioinfo.py`）：实测 `48000 Hz / 32-bit float / 2ch`，
  这是主机混音格式、不是蓝牙码率，界面如实标注、不伪造 kbps。
- 真实码率由主机编码决定：Windows 只协商 SBC/AAC（约 200~330 kbps）。

## 5. 功能 ID 体检（`0x0403`，值 `01`）

| feature | ack | 含义 |
|---|---|---|
| 0x04 | 00 | 佩戴检测 |
| 0x05 | 00 | 未标注 |
| 0x06 | 00 | 游戏模式 |
| 0x0B | 00 | 听力增强 |
| 0x11 | 00 | 双设备连接 |
| 0x13 / 0x1C / 0x27 / 0x28 | 02 | 拒绝 |
| 0x18 | 见上 | Hi-Res |
| 0x1B / `0x0422` | — | **会让耳机断链**，未采用 |

## 6. 推送与其它

| 项 | 结果 |
|---|---|
| `0x0200` 可推送事件 | `01 02 03 04 08 0B F1 F2 F3` |
| `0x0205` 批量注册 | 无 ack，回退逐条 `0x0201` |
| 电量推送 `0x0204#1` | `01 01 02 64` → 右耳 100%，实时刷新 |
| 电量查询 `0x0106` | `00 03 01 64 02 64 03 1E`；**只上报不在盒内的耳机** |
| 降噪推送 `0x0204#3` | 本机改降噪时不推送，必须回读 |
| 查找耳机 `0x0400` | `[01]` 响铃 / `[00]` 停止，ack `00` |
| 空闲 / 回盒 | 耳机主动断开 RFCOMM，Windows 仍显示「已连接」 |
| 快速重连 | 易撞 `WinError 10048`，需 1.5s 以上间隔 |
